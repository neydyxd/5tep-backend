## Ограничения проекта

- Только iPhone, portrait, iOS 16.0+, совместимость с iPad для прохождения App Review
- Английский язык основной, русский дополнительный
- Никаких платных сторонних сервисов и ключей: системные API iOS и этот бэкенд
- Вес релизов — целевой показатель: 45 / 95 / 290 / 480 МБ при лимитах 50 / 100 / 300 / 500
- Аккаунт по логину и паролю, вход необязателен

## Сервер
Аккаунт приложения 5tep: регистрация, вход, профиль, удаление аккаунта. Приложение
работает без сети целиком — бэкенд нужен только для аккаунта и (с релиза 2.0) для
синхронизации профиля между устройствами.

Стек: NestJS 11 (TypeScript), PostgreSQL 17, TypeORM, Argon2id, Vitest.

## Запуск

```bash
cp .env.example .env        # порт базы правится здесь
docker compose up -d        # PostgreSQL
npm ci
npm run migration:run       # схема
npm run start:dev           # http://localhost:3000
```

Проверки: `npm run build` (типы) · `npm run lint` · `npm test` (модульные) ·
`npm run test:e2e` (сквозные, нужна поднятая база).

## Эндпоинты

| Метод | Путь | Тело | Ответ | Ошибки |
|---|---|---|---|---|
| `POST` | `/auth/register` | `{login, password}` | `201 {token, userId, login, profile}` | `409` логин занят, `422` неверный формат |
| `POST` | `/auth/login` | `{login, password}` | `200 {token, userId, login, profile}` | `401` неверная пара, `429` + `Retry-After` |
| `POST` | `/auth/logout` | — (Bearer) | `204` | `401` |
| `GET` | `/profile` | — (Bearer) | `200 {goalSteps, heightCm, weightKg, preferredTime, streakDays}` | `401` |
| `PATCH` | `/profile` | `{goalSteps?, heightCm?, weightKg?, preferredTime?, streakDays?}` | `200 {profile}` | `401`, `422` |
| `DELETE` | `/account` | — (Bearer) | `204`, каскадно удаляет профиль и сессии | `401` |

Ограничения значений совпадают на клиенте, в DTO и в `CHECK`-ограничениях базы:
цель 3 000–30 000 шагов с шагом 1 000, рост 100–230 см, вес 30–250 кг,
удобное время — `morning` · `midday` · `evening` · `late-evening`.

## Безопасность

- Пароль хранится только как хеш Argon2id (19 MiB, две итерации), в логи не попадает.
  Ответ на ошибку валидации содержит имена полей и правил, но не значения.
- Логин занят независимо от регистра (уникальный индекс по `lower(login)`),
  при входе регистр не важен.
- «Нет такого логина» и «неверный пароль» отвечают одинаково — `401 Invalid login or
  password`; пароль сверяется и при отсутствии логина, чтобы время ответа не выдавало
  существующие логины.
- Не больше пяти попыток входа в минуту на логин и на адрес, дальше `429` с
  `Retry-After`. Сверх этого действует общий лимит 60 запросов в минуту на адрес.
- Токен сессии — 32 случайных байта; в базе лежит только его SHA-256. Живёт 30 дней и
  продлевается при активности. Выход удаляет одну сессию, остальные продолжают работать.
- HTTPS терминируется прокси; `trust proxy` включён, чтобы лимиты считались по адресу
  клиента. Заголовки безопасности ставит `helmet`.

## Структура

| Путь | Что внутри |
|---|---|
| `src/auth/` | регистрация, вход, сессии, ограничение попыток, guard |
| `src/profile/` | чтение и правка профиля, удаление аккаунта |
| `src/users/` | сущности пользователя и профиля с границами значений |
| `src/database/` | источник данных для CLI и миграции |
| `test/` | сквозной сценарий аккаунта |

Мобильное приложение в Debug-сборке обращается к `http://localhost:3000`, поэтому для
работы с ним достаточно поднять сервер и базу командами выше.
