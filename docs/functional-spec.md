# 5tep — функциональная спецификация, релиз 1.0.0

Документ описывает логику приложения: данные, действия, состояния, переходы и расчёты.
Дизайн-этап без него не начинается — экран отказа в доступе, пустое состояние и ошибку
нельзя нарисовать, не зная поведения.

## 0. Принципы

1. **Только бесплатные системные API и собственный бэкенд.** Никаких сторонних платных
   сервисов: ни СМС, ни Google Maps, ни пуш-платформ, ни облачной аналитики.
2. **Offline-first.** Шаги, прогулки, маршруты и план работают без сети целиком. Бэкенд нужен
   для аккаунта и (с релиза 2.0) для синхронизации между устройствами.
3. **Разрешение запрашивается в момент пользы**, а не на старте. Отказ никогда не ломает
   приложение — сценарий продолжается в урезанном виде.
4. **Аккаунт необязателен.** «Продолжить без аккаунта» доступно всегда (App Review 5.1.1(v)).

## 1. Аутентификация

### Способ

Логин (латиница/цифры/`._-`, 3–32 символа) и пароль. Регистрация и вход — на собственном
бэкенде. Сторонних провайдеров входа нет намеренно: любой сторонний вход обязывает добавить
Sign in with Apple (App Review 4.8).

### API

| Метод | Тело | Ответ | Ошибки |
|---|---|---|---|
| `POST /auth/register` | `{login, password}` | `201 {token, userId, profile}` | `409` логин занят, `422` слабый пароль/неверный формат логина |
| `POST /auth/login` | `{login, password}` | `200 {token, userId, profile}` | `401` неверная пара, `429` слишком много попыток |
| `POST /auth/logout` | — (Bearer) | `204` | `401` |
| `GET /profile` | — (Bearer) | `200 {profile}` | `401` |
| `PATCH /profile` | `{goalSteps, heightCm, weightKg, preferredTime}` | `200 {profile}` | `401`, `422` |
| `DELETE /account` | — (Bearer) | `204`, каскадно удаляет данные | `401` |

### Правила безопасности

- Только HTTPS. Пароль в теле запроса, никогда в query и никогда в логах.
- На сервере хранится **только хеш**: Argon2id (или bcrypt, cost ≥ 12) с солью.
- Клиент не хранит пароль. Токен сессии — в **Keychain** (`kSecAttrAccessibleAfterFirstUnlock`),
  не в `UserDefaults`.
- Ограничение попыток: 5 в минуту на логин и на IP, дальше `429` с `Retry-After`.
- Ответ на «нет такого логина» и «неверный пароль» одинаковый: `401 «Неверный логин или пароль»` —
  чтобы нельзя было перебором узнать существующие логины.
- Токен живёт 30 дней, продлевается при активности. `401` от любого эндпоинта → выход на экран входа
  с сохранением локальных данных.

### Валидация на клиенте (до запроса)

| Поле | Правило | Текст ошибки |
|---|---|---|
| Логин | 3–32 символа, `[A-Za-z0-9._-]` | «Логин: 3–32 символа, латиница, цифры, точка, дефис» |
| Пароль | ≥ 8 символов, хотя бы одна буква и одна цифра | «Пароль: минимум 8 символов, буква и цифра» |
| Повтор пароля (регистрация) | совпадает | «Пароли не совпадают» |

### Режим без аккаунта

Локальный профиль с `localUserId` (UUID в Keychain). Все данные пишутся локально. При
последующей регистрации локальные данные привязываются к созданному аккаунту одним запросом
`POST /sync/adopt` — ничего не теряется. Приватный раздел (дневник, релиз 2.0) в этом режиме
доступен, но не переносится между устройствами — об этом сказано текстом на экране.

## 2. Модель данных

Локально (Core Data / файлы в `Documents`), тот же набор — на бэкенде с релиза 2.0.

```
Profile:  userId, login?, goalSteps, heightCm, weightKg, preferredTime, streakDays, createdAt
DayStat:  date, steps, distanceM, activeMinutes, kcal, closedSegments
Walk:     id, startedAt, finishedAt, distanceM, durationS, avgPaceSPerKm, steps, track[], checkpoints[]
TrackPoint: lat, lon, timestamp, accuracy
Checkpoint: id, walkId, photoPath, lat, lon, takenAt
PlannedWalk: id, date, startTime, durationMin, title, calendarEventId?
```

Фотографии чекпоинтов лежат в `Documents/walks/<walkId>/`, в галерею **не** попадают.
В галерею сохраняется только итоговая карточка прогулки — по явному нажатию.

## 3. Расчёты

| Величина | Формула | Примечание |
|---|---|---|
| Шаги за день | `CMPedometer.queryPedometerData(from: startOfDay, to: now)` | системный счётчик, без HealthKit |
| Размер сегмента | `goalSteps / 5` | при цели 10 000 → 2 000 |
| Сегмент `i` закрыт | `steps >= (i + 1) * goalSteps / 5` | `i` от 0 до 4 |
| Прогресс текущего сегмента | `(steps - i * size) / size`, обрезать в `0…1` | для мятной дуги на кольце |
| Дистанция | `CMPedometer.distance`; если `nil` — `steps × heightCm × 0.415 / 100` | метры |
| Ккал | `steps × weightKg × 0.00064`, округление до целого | при 70 кг ≈ 0,045 ккал на шаг |
| Темп прогулки | `durationS / (distanceM / 1000)` → мин:сек на км | при дистанции < 100 м темп не показывается («—») |
| Серия дней | подряд идущие дни, где `closedSegments >= 5`; прерывается при пропуске. Отсчёт идёт от сегодня, если сегодня уже закрыт, иначе от вчера: незакрытый текущий день не обрывает серию, которую он ещё может продолжить | считается локально |
| «+N к вчера» | `steps - вчерашние steps`, показывается только при `> 0` | |

Единицы: метрические. Дистанция < 1 км показывается в метрах («840 м»), дальше — в км с одним
знаком («4,8 км»).

## 4. Экраны релиза 1.0

### 01 · Онбординг (`onboarding`)

- **Данные:** ничего не читает; собирает цель, рост, вес, удобное время прогулки.
- **Действия:** 4 шага квиза, «Далее», «Назад», выбор варианта. На последнем шаге — «Начать».
- **Правила:** цель 3 000–30 000 с шагом 1 000; рост 100–230 см; вес 30–250 кг. Ввод за
  границами — поле краснеет, «Далее» неактивна.
- **Состояния:** `error` — неверное значение в поле с пояснением под ним.
- **Переходы:** «Начать» → `access`. Показывается один раз; повторно доступен из `settings`.

### 02 · Вход и регистрация (`auth`)

- **Данные:** ничего локального; отправляет пару логин/пароль на бэкенд.
- **Действия:** переключатель «Вход | Регистрация», ввод логина и пароля, показать/скрыть пароль,
  «Войти» / «Создать аккаунт», «Продолжить без аккаунта».
- **Состояния:**
  - `loading` — кнопка в состоянии ожидания, поля заблокированы;
  - `error` — валидация клиента (см. 1.4) или ответ сервера: `401` «Неверный логин или пароль»,
    `409` «Логин занят», `429` «Слишком много попыток, попробуйте через N сек», нет сети —
    «Нет соединения. Можно продолжить без аккаунта».
- **Переходы:** успех → `home`; «Продолжить без аккаунта» → `home` в локальном режиме.
- **Правило:** экран пропускается, если в Keychain есть валидный токен или `localUserId`.

### 03 · Доступы (`access`)

- **Данные:** текущий статус четырёх разрешений.
- **Действия:** на каждое разрешение — кнопка «Разрешить», вызывающая системный запрос;
  «Продолжить» уходит дальше независимо от решений.
- **Правила:** запрашивается ровно то, что нужно сценарию: геопозиция, камера, добавление в
  галерею, календарь. Под каждым — одна строка о том, что перестанет работать без него.
  Уже выданные показываются галочкой и не запрашиваются повторно.
- **Состояния:** `error` — разрешение отклонено: строка меняется на «Отклонено» и кнопку
  «Открыть настройки» (`UIApplication.openSettingsURLString`).
- **Переходы:** «Продолжить» → `home`.

### 04 · Сегодня (`home`)

- **Данные:** шаги за сегодня (CoreMotion), дистанция, активные минуты, ккал, серия дней,
  ближайшая запланированная прогулка.
- **Действия:** «Начать прогулку» → `walk-live`; тап по карточке плана → `plan`;
  тап по кольцу → `stats` (с релиза 2.0, до этого не кликабельно).
- **Состояния:**
  - `empty` — первый день или нет данных счётчика: кольцо серое, «0», подпись «Начните двигаться —
    первые шаги появятся через минуту»;
  - `loading` — счётчик опрашивается: кольцо-скелетон, цифра скрыта;
  - `error` — CoreMotion недоступен (`CMPedometer.isStepCountingAvailable == false`):
    «Счётчик шагов недоступен на этом устройстве», прогулки при этом работают;
  - `прогулка приостановлена` — приложение сворачивали во время прогулки: карточка с накопленной
    дистанцией и временем, «Продолжить» возвращает на `walk-live`, «Завершить» ведёт на
    `walk-summary`.
- **Обновление:** при возврате на экран и по таймеру раз в 30 секунд, пока экран виден.

### 05 · Прогулка (`walk-live`)

- **Данные:** трек с `CLLocationManager` (`desiredAccuracy = best`, `distanceFilter = 10 м`),
  дистанция, время, темп, число чекпоинтов, прогресс текущего сегмента.
- **Действия:** «Фото-чекпоинт» (камера, снимок привязывается к текущей точке), «Пауза»/
  «Продолжить», «Завершить».
- **Правила:**
  - точки с `horizontalAccuracy > 50 м` отбрасываются;
  - на паузе трек не пишется, время не идёт;
  - прогулка короче 100 м или 60 секунд при завершении предлагается к удалению
    («Слишком короткая прогулка. Сохранить?»);
  - экран не гасится во время прогулки (`isIdleTimerDisabled`).
- **Состояния:**
  - `loading` — ждём первую точку: «Ищем спутники», трек пуст;
  - `error` — доступ к геопозиции не выдан: карта неактивна, поверх — объяснение и «Открыть
    настройки»;
  - `слабый сигнал GPS` — при `accuracy > 50 м` дольше 15 секунд: чип статуса становится
    «GPS слабый», под статистикой — баннер с объяснением, что точки не пишутся;
  - `слишком короткая прогулка` — подтверждение при завершении прогулки короче 100 м или
    60 секунд: «Удалить прогулку» / «Всё равно сохранить».
- **Переходы:** «Завершить» → `walk-summary`.

### 06 · Итог прогулки (`walk-summary`)

- **Данные:** маршрут на карте, дистанция, время, темп, шаги, лента чекпоинтов, сколько
  сегментов закрыто этой прогулкой.
- **Действия:** «Сохранить карточку» (рендер `UIGraphicsImageRenderer` → `UIImageWriteToSavedPhotosAlbum`),
  «Удалить прогулку» (с подтверждением), тап по чекпоинту — просмотр фото.
- **Состояния:**
  - `loading` — карточка рендерится;
  - `error` — нет доступа к добавлению в галерею: «Разрешите добавление в Фото, чтобы сохранить
    карточку» + «Открыть настройки». Сама прогулка сохранена локально независимо от этого;
  - `удаление · подтверждение` — диалог с перечнем удаляемого (маршрут и снимки), «Удалить
    прогулку» / «Отмена»;
  - `просмотр фото-чекпоинта` — полноэкранный просмотр снимка на тёмном фоне: счётчик «1 / 2»,
    время и расстояние от старта, «Показать на маршруте».
- **Переходы:** назад → `routes` или `home`.

### 07 · Маршруты (`routes`)

- **Данные:** список прогулок, отсортированный по дате убыванием: миниатюра трека, дата,
  дистанция, темп, число фото.
- **Действия:** тап → `walk-summary`; фильтр по длине (все / до 3 км / 3–7 км / больше 7 км);
  свайп — удалить с подтверждением.
- **Состояния:** `empty` — «Пока ни одной прогулки» + кнопка «Начать прогулку»;
  `loading` — скелетоны трёх карточек; `error` — «Не удалось прочитать историю» + «Повторить»;
  `свайп · удаление` — карточка сдвинута влево, справа открыта красная кнопка удаления, поверх —
  то же подтверждение, что и на `walk-summary`.

### 08 · План (`plan`)

- **Данные:** запланированные прогулки на 7 дней; занятость из календаря (`EKEventStore`,
  доступ на чтение) для подсказки свободных слотов.
- **Действия:** «Запланировать прогулку» → выбор дня, длительности (20/40/60 мин) и слота;
  «Добавить в календарь» создаёт `EKEvent` с напоминанием за 15 минут; удаление плана удаляет
  и событие по `calendarEventId`.
- **Правила:** слоты ищутся в диапазоне 7:00–22:00, длительность + 10 минут запаса, не
  пересекаясь с существующими событиями; предлагаются три ближайших варианта,
  приоритет — `preferredTime` из профиля.
- **Состояния:** `empty` — «На этой неделе прогулок не запланировано»;
  `error` — нет доступа к календарю: план работает локально, вместо подсказок слотов —
  строка «Разрешите доступ к календарю, чтобы подбирать свободное время» + «Открыть настройки»;
  `новая прогулка` — шит поверх экрана: день недели, длительность 20/40/60 мин с оценкой шагов,
  три подобранных слота (первый — ближайший к `preferredTime`), «Добавить в календарь»;
  `добавлена в календарь` — подтверждение с датой, временем и временем напоминания, «Готово» /
  «Изменить время»; `удаление · подтверждение` — «Убрать из плана» с предупреждением, что
  событие в календаре и напоминание удалятся тоже.
- **Переходы:** карточка плана на `home` ведёт сюда.

### 09 · Профиль (`profile`)

- **Данные:** логин или «Без аккаунта», цель, серия дней, суммарная дистанция и число прогулок,
  достижения. Достижений восемь, все считаются из локальной истории: первый закрытый день,
  первая неделя (7 дней подряд), десять маршрутов, сто километров, ранняя птица (прогулка до
  8:00), фотодневник (25 чекпоинтов), долгая прогулка (10 км за раз), месяц подряд.
- **Действия:** изменить цель (тот же пикер, что в онбординге), «Войти / Создать аккаунт» в
  локальном режиме, «Выйти» при активной сессии.
- **Состояния:** `empty` — нет достижений: «Закройте первый день, чтобы получить первое
  достижение»; `error` — `PATCH /profile` не прошёл: «Изменения сохранены на устройстве,
  синхронизируем позже»; `изменение цели` — шит с теми же вариантами цели, что в онбординге,
  и кнопкой «Сохранить цель».
- **Правило:** «Выйти» стирает токен, локальные данные остаются.

### 10 · Настройки (`settings`)

- **Данные:** статусы разрешений, единицы, язык, версия приложения.
- **Действия:** управление доступами (переход в системные настройки), язык приложения
  (строка показывает текущий и открывает системные настройки приложения — списком языков
  владеет iOS, отдельного переключателя в приложении нет), «Пройти онбординг заново»,
  «Удалить данные на устройстве», «Удалить аккаунт» (`DELETE /account`). Единицы —
  метрические по ТЗ, поэтому строка «Единицы» показывает значение без выбора.
- **Правила:** оба удаления — с подтверждением и явным перечнем того, что будет удалено;
  удаление аккаунта разлогинивает и стирает локальные данные.
- **Состояния:** `подтверждение удаления аккаунта` и `подтверждение удаления данных` — два
  отдельных диалога, каждый перечисляет, что именно исчезнет; `error` — запрос на удаление
  аккаунта не прошёл: «Не удалось удалить аккаунт. Попробуйте позже» без частичного удаления.
- **Ограничение:** на экране только то, что описано здесь. Экспорт прогулок в файл и локальные
  напоминания в релиз 1.0 не входят — из макетов удалены.

## 5. Сквозные правила

| Ситуация | Поведение |
|---|---|
| Нет сети | Всё, кроме входа/регистрации и синхронизации профиля, работает. Баннер не показывается — приложение локальное по замыслу |
| Первый запуск | `onboarding` → `access` → `auth` (пропускаемый) → `home` |
| Разрешение отклонено | Экран работает, зависящая фича заменяется объяснением и кнопкой «Открыть настройки». Повторный системный запрос не вызывается — iOS его не покажет |
| Токен истёк (`401`) | Молча на `auth`, локальные данные не трогаются |
| Приложение свёрнуто во время прогулки | Релиз 1.0: запись останавливается, накопленное сохраняется, при возврате — «Прогулка приостановлена». Фоновая запись появляется в 3.0 с `NSLocationAlwaysAndWhenInUse` |
| Смена часового пояса / полночь во время прогулки | Прогулка относится к дню своего начала |
| Удаление данных | Стираются локальная база и папка `walks/`, профиль сбрасывается к значениям онбординга |
| Тема оформления | Берётся системная. Светлая и тёмная поддержаны полностью: экраны, тексты, иконки, карта, фотографии, интерактивные элементы. Переключателя в настройках нет — приложение следует за системой |
| Смена темы при работающем приложении | Перерисовка мгновенная, состояние экрана и запись прогулки не сбрасываются: цвета берутся из семантических ролей, а не из констант |

## 6. Используемые API — все бесплатные

| Задача | API | Платно? |
|---|---|---|
| Шаги, дистанция | `CoreMotion` / `CMPedometer` | нет |
| Геопозиция и трек | `CoreLocation` / `CLLocationManager` | нет |
| Карта и маршрут | `MapKit`: подложка системная, трек и чекпоинты — свои оверлеи | нет |
| Камера | `AVFoundation` / `AVCaptureSession` | нет |
| Сохранение в галерею | `Photos` / `UIImageWriteToSavedPhotosAlbum` | нет |
| Календарь | `EventKit` / `EKEventStore` | нет |
| Хранение токена | `Security` / Keychain | нет |
| Локальная база | `CoreData` | нет |
| Тема оформления | `UITraitCollection` / SwiftUI `@Environment(\.colorScheme)`, цвета в Asset Catalog с вариантами Any/Dark | нет |
| Аккаунт и синхронизация | собственный бэкенд | только хостинг |

Сторонних зависимостей нет вовсе: карту рисует системный `MapKit`, остальное — нативные API iOS
и собственный бэкенд. Платных SDK нет. Шрифты — Manrope и JetBrains Mono (SIL OFL), иконки —
Lucide (ISC), данные о маршрутах — OpenStreetMap (ODbL), рельеф — SRTM (public domain), модели
распознавания — из галереи Apple; атрибуция на экране «Источники» в настройках.

Ни одной внешней интеграции с API-ключом нет ни в одном релизе: всё, что не отдаёт нативный
API iOS, делает собственный бэкенд. Это касается и двух капабилити релиза 4.0, где такая
интеграция была бы напрашивающейся:

- **`voip` — голосовая связь на прогулке.** `PushKit` поднимает `CallKit` с системным экраном
  вызова, звук идёт `AVAudioEngine` → сжатие → WebSocket до нашего сервера → второе
  устройство; эхо и шум снимает iOS через `AVAudioSession` в режиме `.voiceChat`. Twilio,
  Agora и прочие сервисы не используются; WebRTC с TURN-сервером тоже не берём — при релее
  NAT-обход не нужен, а живых официальных сборок WebRTC под iOS нет. Сценарий короткий:
  перекинуться словом на совместной прогулке, а не заменить мессенджер.
- **`NSBluetoothAlwaysUsageDescription` — внешний пульсометр.** Экран «Датчики» обязан быть
  рабочим без физического датчика: ревьюер Apple железа не имеет, и «функция не работает» —
  готовый реджект. Датчик автоматизирует то, что доступно руками, и не является единственным
  путём к экрану.
